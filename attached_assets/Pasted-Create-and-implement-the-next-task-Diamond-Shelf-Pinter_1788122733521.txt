Create and implement the next task: Diamond Shelf Pinterest Creative Renderer MVP.

Build the deterministic visual-rendering layer on top of the completed Pinterest Pin Proposal Engine.

This task creates actual Pinterest-ready visual previews from REVIEW proposals.

Do not implement Pinterest OAuth, scheduling, publishing, analytics, automatic approval, or AI-generated branded products.

Keep PUBLISHING_ENABLED=false.

1. Creative output specification

Render Pinterest creatives at exactly:

1000 × 1500 pixels

Aspect ratio:

2:3

Primary output:

PNG

Rendering must be deterministic: identical source inputs + identical template version must produce visually identical output.

Prefer a server-side deterministic SVG → PNG rendering architecture compatible with the existing project. Satori/resvg or an equivalent production-safe renderer is appropriate if compatible with the current stack.

Do not introduce a separate microservice unless genuinely necessary.

2. Authentic Shopify product image is mandatory

The rendered product itself must always come from the authentic Shopify/catalog image belonging to that exact imported product.

Never:

generate a branded perfume bottle with AI
redraw the bottle
substitute another product
reconstruct logos
alter brand text
replace packaging
hallucinate missing product imagery

The source image relationship must be verified against the imported Shopify image record before rendering.

If the image cannot be verified, rendering must fail safely.

Background removal may eventually be supported, but any extracted product foreground must originate from the authentic Shopify image and must not change packaging, logos, bottle geometry, or labeling.

For this MVP, prefer safe containment of the authentic source image rather than aggressive image manipulation.

3. Prevent arbitrary-image fetching

Do not allow the renderer to fetch arbitrary external URLs.

It may use only image URLs associated with the selected imported Shopify product and approved catalog-media provenance.

Add reasonable:

download timeout
file-size limits
image decode validation
MIME validation
dimension validation

Prevent SSRF or arbitrary URL fetching.

5. Initial four creative templates

Implement these four deterministic templates:

A. Luxury Product Spotlight

Large product-focused editorial layout.

Important: “Luxury Product Spotlight” is the internal template name.

Using this visual template must NOT automatically produce the word “luxury” in consumer-facing copy.

The rendered text may claim that something is luxury only if the proposal has explicit source evidence supporting that claim.

B. Product + Classification

Suitable for supported facts such as:

Arabian Fragrance
Designer Fragrance
Niche Fragrance
Men's Fragrance
Women's Fragrance
Unisex Fragrance

Only render classifications present in the approved ProductIntelligence/proposal evidence.

C. Gift Guide / Gift Set

Designed for explicitly identified gift sets.

Do not describe ordinary single products as gift sets.

D. Editorial Product Pick

General-purpose premium editorial treatment for products where narrower classifications are unavailable or inappropriate.

7. Text fitting and layout safety

Implement deterministic text fitting.

Handle:

long product names
long brands
long classifications
two-line and three-line titles

Text must never:

overlap the product
overflow the canvas
leave the canvas
collide with the Diamond Shelf branding
become unreadably small

Define reasonable maximum lengths and fallback layout behavior rather than silently clipping important text.

Add automated tests for extreme-length titles.

8. Product-image layout

Preserve product proportions.

Do not stretch or distort images.

Use contain/fit behavior appropriate to each template.

Images should remain visually prominent without colliding with typography.

Account for source images with:

white backgrounds

tall bottles
wide gift sets
candles
beauty/body products
9. Creative specification and reproducibility

Persist or otherwise maintain a canonical creative specification containing at least:

source image provenance

supporting text

Generate a deterministic SHA-256 creative fingerprint from the canonical rendering specification.

If practical, also calculate a perceptual image hash for rendered images so future duplicate detection can identify visually near-identical Pins.

10. Template versioning

Templates must be versioned.

Example conceptually:

editorial_product_pick:v1

A later visual redesign must not silently change the rendering definition of historical creatives.

Existing creative records should retain the template version with which they were rendered.

11. Rendering/storage architecture

Do not store large PNG binaries directly inside ordinary relational database columns.

Keep creative metadata/specification in PostgreSQL.

Use a clean rendering/storage abstraction so durable object storage/CDN can be introduced before Pinterest production publishing.

For the current MVP, use the simplest reliable approach supported by the existing Replit application while keeping that storage boundary clean.

The approval UI must be able to display the rendered result.
